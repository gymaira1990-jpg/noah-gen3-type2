## 二、核心设计哲学

### 2.1 模块化NCP体系

原铸诺亚的核心架构决策是将所有能力拆解为**NCP模块**（Noah Capability Package），每个模块满足：

- **独立可维护**：有独立的版本号、状态、变更记录
- **资源锚定**：明确依赖的数据库表、技能文件、配置文件
- **续接指令**：中断后3步可找回状态继续推进

### 2.2 从原铸到三代二型的进化路径

```
原铸诺亚 (noah-prime)      ← 实战: 数万轮对话, 7 NCP模块, 生产运行
    │
    ├── 提炼·通用化
    │      ↓
    │  三代二型 (noah-gen3-type2)  ← 解耦为通用方案, MIT 许可证
    │   ├── 01 上下文管理组装系统  🟢 生产就绪
    │   ├── 02 Mnemosyne-记忆宫殿  🟢 生产就绪
    │   ├── 03 认知AI底座         📄 方案阶段
    │   └── 04 原铸诺亚·二代一型  🟢 生产运行 ← 你在这里
    │
    └── 实战验证·反向反馈
           ↓
        改进日志 → 经验教训 → NCP模块版本迭代
```

### 2.3 关键架构决策

| 决策 | 选择 | 理由 |
|:-----|:-----|:------|
| Agent框架 | Hermes Agent | CLI原生，钩子系统成熟，Gateway多端分发 |
| 记忆存储 | PostgreSQL + pgvector | 双库分离（真相+索引），比ChromaDB更稳定 |
| 路由策略 | P4 Router（自定义） | 余额感知+降级链，比OpenRouter更可控 |
| 任务驱动 | TFC + OS cron | 级联任务流，Hermes cron + OS cron双保险 |
| 安全架构 | 三层钩子门闸 | 输入过滤/工具决策/输出审查，代码锁死 |
| 灾备方案 | 4槽位 + rsync | RPGSave风格，GZ服务器异地灾备 |

## 三、模块依赖图谱

### 3.1 运行时调用链

```
用户输入
  │
  ├── NCP-011 安全门闸（输入过滤钩子）  ── 拦截恶意/越权输入
  │
  ├── NCP-010 记忆检索（上下文组装）    ── 提取历史+知识
  │     └── PostgreSQL pgvector
  │
  ├── NCP-007 P4 Router（路由决策）     ── 选模型+降级
  │     └── route_vectors (pgvector HNSW)
  │
  ├── LLM API 调用                      ── DeepSeek/豆包/本地
  │
  ├── NCP-011 安全门闸（输出审查钩子）  ── 过滤敏感内容
  │
  ├── NCP-012 TFC（任务追踪）           ── 记录为tfc卡片
  │
  └── NCP-013 FC存档（自动备份）        ── 定时灾备
```

### 3.2 数据流依赖

```
NCP-012 (TFC任务) ─→ 所有模块 (任务管理)
NCP-013 (FC存档)  ─→ 所有模块 (灾备保障)
NCP-010 (记忆)    ─→ NCP-008 (知识吸收产物存入记忆)
NCP-011 (安全)    ─→ 所有 LLM 交互 (钩子拦截)
NCP-009 (进化)    ─→ 无硬依赖 (作用于方法论层面)
NCP-007 (路由)    ─→ 无硬依赖 (独立工程)
NCP-008 (知识)    ─→ 无硬依赖 (纯技能)
```

## 四、版本管理规范

### 4.1 三轨同步

| 版本轨 | 位置 | 更新时机 |
|:-------|:-----|:---------|
| VERSION.json | `运营/VERSION.json` | 每次版本变更手动更新 |
| NCP模块文件 | `模块/NCP-*.md` | 对应模块变更时更新 |
| PG version_registry | `noah_local` | 每次部署更新 |

### 4.2 版本号规则

```
v2.0.2
││└── 补丁: 文档修正、小bug修复
│└── 次版本: 功能增减、模块新增/退役
└── 主版本: 架构级变更、框架升级
```

## 五、常见开发模式

### 5.1 新增一个NCP模块

```bash
# 1. 复制模板
cp NCP模块模板.md 模块/NCP-0XX-模块名称.md

# 2. 填入元信息 + 资源锚定 + 续接指令

# 3. 更新项目注册.md
# 4. 如果涉及数据表 → 写 schema.sql → psql 执行
# 5. 如果涉及新Skill → 创建 skill → 注册到 Hermes
# 6. git tag 新版本
```

### 5.2 修复文档-代码偏差

```
发现偏差 → 记录到技术说明书的偏差矩阵 → 修复代码或更新文档
→ 更新 VERSION.json 补丁号 → git commit + tag
```
