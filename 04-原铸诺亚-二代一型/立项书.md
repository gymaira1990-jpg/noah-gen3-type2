# 原铸诺亚·二代一型 — 立项书

> **项目编号**: 04 | **版本**: v2.0.2 | **日期**: 2026-05-22

---

## 一、为什么做

原铸诺亚（Primaris Noah）是诺亚家系的第一个生产级实现——从顶层设计到底层代码、从记忆系统到安全门闸、从任务流到灾备体系的完整闭环。它不是原型，而是「已经在跑、一直在用」的真实系统。

但此前的项目注册是管理体系层面的（7个NCP模块的版本锚定），而不是技术架构层面的完整分析。本项目的目标是：**对原铸诺亚做一次全模块微观CT扫描——每个模块的代码量、实现状态、真实依赖、已知问题、与文档的偏差、以及"成型度"的定量评估。**

## 二、做什么

1. 全量分析原铸诺亚7个NCP模块的实现现状
2. 对每个模块输出：真实代码量 / 功能覆盖率 / 已知未完成项 / 文档-代码偏差
3. 定位已注册但PG中不存在的数据表（version_registry）
4. 定位已设计但未部署的组件（仪表盘HTML、续接脚本）
5. 输出"成型度评分"——每个模块百分比+全系统加权总分
6. 生成面向gen3-type2重构的提取建议

## 三、不做什么

- 不改动原铸诺亚的运行时代码
- 不创建新的NCP模块
- 不改版本号（仅记录现状）

## 四、分析范围

| 维度 | 覆盖 |
|:----|:-----|
| 代码 | 7个NCP模块 + 依赖的Hermes skills + PG数据层 |
| 运行时 | 当前活跃状态、进程健康、DB连接 |
| 文档 | 项目注册/产品手册/功能矩阵 vs 实际代码的一致性 |
| 基础设施 | Hermes配置 / Ollama / PG / 备份 |
| 知识库 | knowledge_entries/cards 的量级与质量 |
| TFC管道 | 已完成 vs 待办 vs 活跃的剩余工作量 |
