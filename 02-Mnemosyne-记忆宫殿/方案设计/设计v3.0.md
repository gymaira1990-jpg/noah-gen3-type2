## 一、整体定位

**Mnemosyne 是一个"仅做记忆"的专用中台。** 它不处理对话，不搞路由，不负责视觉理解——只负责把 AI Agent 发过来的记忆和知识管好存好。

```
AI Agent 是主脑，Mnemosyne 是外挂硬盘。

Agent 做的事:
  - 对话生成（推理）
  - 视觉理解（调用多模态模型）
  - 工具编排（MCP 调用）
  - 上下文管理

Mnemosyne 做的事:
  - 永久记忆存储
  - 多维检索
  - 热度遗忘
  - 自我进化
```

## 四、热度分层

### 4.1 热度公式

```
Heat_Score = 0.4 × normalized(Freq30d) 
           + 0.35 × (1 - normalized(RecencyDays)) 
           + 0.25 × Importance
```

| 维度 | 权重 | 数据来源 |
|:-----|:----:|:---------|
| 访问频率 | 40% | access_count，30 天窗口 |
| 新鲜度 | 35% | last_accessed，越近越热 |
| 重要性 | 25% | 用户反馈 + 自动检测 |

### 4.2 分层阈值

| 层级 | 阈值 | 行为 |
|:-----|:----:|:-----|
| L1 热 | heat_score > 0.7 | 高优先级检索，自动注入 |
| L2 常温 | 0.2 ~ 0.7 | 普通检索命中 |
| L3 冷 | 0.05 ~ 0.2 | 低优先级，需要精确查询才找到 |
| L4 归档 | < 0.05 | 不参与检索，可手动恢复 |

## 五、自我进化（Reflector）

### 5.1 Light 模式（每小时）

1. 热度衰减: `heat_score × 0.95`
2. L4 归档标记: `heat_score < 0.05`
3. 软删除清理: 删除超过 30 天的已删记忆（物理清理）

### 5.2 Deep 模式（每天凌晨 4 点）

1. 冗余检测: `cosine_sim > 0.92` → 合并内容
2. 实体提取: NLP 提取命名实体 → 同步到 AGE
3. 冲突检测: 同一实体的事实矛盾 → 标记人工审核
4. 热度重新归一化: 全局热度重平衡

### 5.3 Writer-Reader 闭环

```
Reader (检索) → 用户反馈 (feedback) → Writer (热度更新)
                                            ↓
                                    Reflector (去重/合并)
                                            ↓
                                    Writer (热度重算)
```

## 六、多模态设计（关键设计决策）

**关键纠正**: 最初设计让 Mnemosyne 自己调豆包 API 做视觉理解——这是错的。

正确的理解：
```
AI Agent 收到用户发的图片
  ↓
Agent 调用自身多模态模型做视觉理解（如 GLM-4.6V-Flash）
  ↓ "这张照片是日落时分的海边，有一个人正在散步..."
Agent 调用 memory_store_multimodal MCP 工具
  ↓ content="日落海边散步描述" + media_type="image" + media_url="..."
Mnemosyne 存入 media_memories 表，自动生成 embedding
  ↓
完成。Mnemosyne 只做存储，不做理解。
```

**Mnemosyne 需要的：**
- media_memories 表（含 content/media_type/media_url/embedding）
- Ollama 做嵌入（qwen3-embedding:0.6b，已有）

**不需要的：** 任何视觉模型、外部 API

## 九、设计决策记录

### 为什么 MCP 协议而不是自定义 API？
MCP（Model Context Protocol）是 Anthropic 推出的 AI Agent 工具标准。用 MCP = 任意兼容客户端（Claude Desktop / Hermes Agent / 自研框架）零适配接入。

### 为什么不用 Docker？
目标服务器已有复杂服务生态。systemd 更符合现有运维习惯，更小开销，更易排查。

### 为什么四维检索？
单一向量搜索在精确术语（如编号/人名）上准确率低。关键词补充因应精确匹配。时序过滤解决"最近"需求。图遍历解决关联查询。

### 为什么不做推理？
记忆和推理是两件事。耦合在一起 = 改记忆时可能影响推理，改推理时可能影响记忆。分离 = 独立迭代、独立升级、独立扩展。

### 三份源文件冲突时为什么以终极版为准？
因为它是 v2.0，在 v1.0 概念设计的基础上做了大量修正和扩展。部署手册 v3.0 是实施细节，终极版 v2.0 是架构方向。方向先于细节。
