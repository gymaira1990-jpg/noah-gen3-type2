# 抽屉级联压缩引擎 · 设计 v2.0

> 状态: ✅ 代码已实现
> 日期: 2026-05-22
> 设计来源: 抽屉概念 + 专家团队评估 + 搜索验证
> (Stingy Context / HOMER / Apple HD-Gist / Auto-Summarization Buffers)
> 冲突化解原则: 「版本认可最新的」+ key 身份制

---

## 核心概念

三层级联: 原始对话 → 抽屉级联 → 记忆管家 → 上下文组装器

```
每轮对话
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│  Tier 1: 抽屉级联                                        │
│                                                          │
│  废话/闲聊 → 噪音过滤 → 不计轮数，不推入抽屉               │
│  项目方案/进度日志 → 自动识别 → PROTECTED 保护             │
│  有效对话 → 去重 → 推入抽屉(N=3, 满则压→递交下一层)        │
│  温度 = 命中次数(非时间), 每轮衰减, L1/L2/L3 分层自动注入   │
└──────────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│  Tier 2: 记忆管家（辅助模型异步处理）                       │
│                                                          │
│  每 N 轮触发:                                              │
│  ├─ 方案渐进摘要: 不重新摘要，只增量更新已有方案摘要         │
│  ├─ 项目进度追踪: 提取任务引用 → 更新项目档案                │
│  ├─ 执行日志保护: 识别日志/决策 → 固化为 PROTECTED         │
│  ├─ 已完成任务向量化: 完成任务 → 向量摘要 → 冷储            │
│  └─ 重复检测: 当前方案 vs 历史方案 → 防重复造轮子           │
│                                                          │
│  输出: 结构化记忆 + 向量索引                                │
└──────────────────────────────────────────────────────────┘
    │ (每次 LLM 调用前)
    ▼
┌──────────────────────────────────────────────────────────┐
│  Tier 3: 上下文组装器（决定最终喂给大模型的 token）          │
│                                                          │
│  组装 → 最精简必要上下文:                                  │
│  ├─ 从 drawer 取: 当前层未满 + 每层最新摘要                 │
│  ├─ 从 temperature 取: L1(≥8) 全量 + L2(≥4) 摘要注入     │
│  ├─ 从向量库搜: 仅当前活跃项目的方案/进度/决策               │
│  ├─ 从向量库搜: 当前话题相关的前期决策(防重复)               │
│  └─ 跳过: 已完成任务、归档方案、无关历史                    │
│                                                          │
│  输出: 组装好的 messages                                  │
│  目标: 每次调用 < 13K tok                                 │
└──────────────────────────────────────────────────────────┘
    │
    ▼
大模型(主模型) — 只做推理，不做记忆
```

## 一、Tier 1 细化：噪音过滤 + 保护识别

### 1.1 废话/闲聊不计轮数

所有 user 消息在 push() 前过噪音过滤器。

```
噪音模式(纯正则, 不调LLM):
  ┌ 单字/短确认: "好", "嗯", "ok", "继续", "知道了", "可以"
  ├ 语气词: "哈哈", "呵呵", "我去", "牛逼"
  ├ 重复指令: /compress, /status 等元命令
  └ 非语义符号: "---", "====", "..."

命中噪音 → log但不计入抽屉轮数, 不触发温度hit
```

### 1.2 项目方案/进度日志自动保护

```
保护模式(纯正则, 不调LLM):

自动 PROTECTED 标记(命中任意一条即保护):
  ├─ 任务引用: 提到编号的方案/进度/任务
  ├─ 设计文档关键词: "设计", "方案", "架构", "决定"
  ├─ 进度日志关键词: "当前状态", "已完成", "下一步"
  ├─ 执行日志关键词: "部署", "安装", "配置", "改动了"
  └─ 错误/纠正: "不对", "错了", "不能这么"

保护行为:
  - 推入抽屉但标记 protected_flag=True
  - 抽屉压缩时跳过 protected 条目(不压缩)
  - 温度系统: heat 锁定, 永不衰减
```

### 1.3 情绪爆发检测

```
情绪爆发模式:
  关键词: "去死", "永久离线", "最后机会", "滚"
  行为: 触发紧急保护, 该轮所有消息标记 PROTECTED
```

## 二、Tier 2：记忆管家（辅助模型）

### 2.1 方案渐进摘要（防遗忘 + 防重复造轮子）

**核心机制**: 不是每次重新摘要，是增量更新。

```
触发时机: 每 N 轮对话后 / 新方案/决策出现时

流程:
  1. 已有该方案摘要? 
     ├─ 有 → 调辅助模型: "以下为已有方案摘要 [旧摘要]
                当前新增讨论 [新对话片段]
                请增量更新摘要, 不删除已有内容, 只添加新信息"
     └─ 无 → 调辅助模型: "提取以下对话中的方案/计划/决策, 
                输出结构化摘要"

  2. 输出到知识库:
     category='project_progress'
     tags=['project:<名称>', 'incremental_summary']
     content=增量更新后的完整摘要

  3. 防重复: 每次更新前搜索知识库，
     检查 tags 是否有重复方案，
     发现重复 → 追加「⚠ 与历史方案X重复」
```

渐进摘要格式:

```
## 方案: <名称>
  上次更新: <时间>
  当前进度: <一句话当前状态>
  已决策: <list>
  待定: <list>
  已完成: <list>
  关联任务: <编号>
  风险/注意: <list>
```

### 2.2 项目进度追踪

```
触发时机: 任务状态变更 / 用户提到"完成/做完了/搞定了"

流程:
  1. 在对话中提取任务引用
  2. 比对当前任务数据库状态
  3. 如果发现进度更新但任务状态未变 → 
     自动生成进度日志条目(不自动改状态, 只记录)
  4. 进度日志写入知识库:
     category='progress_log'
```

### 2.3 执行日志保护

```
当检测到以下模式时:
  "执行了/改了/部署了/配置了/安装了..."
  → 提取为独立 memory entry (category='execution_log')
  → 标记 PROTECTED
  → 在 context assembler 中该会话期间始终注入

目的: 防止大模型忘记"刚才做了什么"
```

### 2.4 已完成任务向量化冷储

```
当任务状态变为 completed/done:
  1. 收集该任务的所有相关对话摘要
  2. 调辅助模型压缩为一个最终摘要(300-500 tok)
  3. 写入知识库:
     category='completed_task'
     tags=['task:<编号>', 'archive']
     content=最终摘要
  4. 该条目不进入上下文组装器的默认注入
     只在搜索命中时返回

目的: 已完成任务不占用活跃上下文,
      但需要时可以通过语义搜索找回,
      防止"我记得做过但这个事"的尴尬。
```

## 三、Tier 3：上下文组装器

### 3.1 组装公式

```
最终上下文 = 
  [system prompt] 
  + [角色定义 + 技能]
  + [drawer context: 当前层未满 + 每层最新摘要]
  + [temperature L1: heat≥8 条目] (cap 20条 × 80tok)
  + [temperature L2: heat≥4 条目] (cap 50条 × 60tok)
  + [project context: 仅当前活跃项目的方案摘要] (从向量库搜)
  + [decision context: 相关决策, 仅当前话题] (从向量库搜)
  + [execution log: 本轮已做的操作] (从 temperature 的即时日志)
  + [user message]

不注入:
  - 已完成任务的全文
  - 归档方案
  - 寒喧历史
  - 无关项目资料
```

### 3.2 相关性判定

```
query = 提取当前用户消息中的:
  - 任务编号
  - 项目名称
  - 关键词
  - 如果是延续话题 → 用上轮 summary 的 key

搜索 scope:
  - 仅当前活跃项目(不是全部条目)
  - 仅近期(72小时内或 heat≥2)
  - 仅相关(向量相似度 ≥ 阈值)
```

### 3.3 目标 token 预算

| 组件 | 目标 Token | 说明 |
|:-----|:----------:|:-----|
| system prompt | ~500 | 固定的角色+规则 |
| 角色定义+技能 | ~2000 | 身份+技能注入 |
| drawer context | ~2000 | 当前层+每层最新 |
| L1 injection | ~1600 | 20条×80tok |
| L2 injection | ~3000 | 50条×60tok(cap) |
| project context | ~1000 | 当前项目摘要 |
| decision context | ~500 | 相关决策 |
| user message | ~2000 | 当前输入 |
| **总计** | **< 13K** | **不是 200K** |

## 四、冲突化解矩阵（保护 vs 去重 vs 更新）

### 核心原则

**版本认可最新的**。

**三个问题正交解耦:**
- 保护 = 生命周期问题（删不删）
- 去重 = 身份问题（是不是同一个）
- 更新 = 版本问题（内容替不替换）

**用 key 身份制解耦:**
```
去重规则: 同一 key 不重复推入
保护规则: 保护阻止删除/压缩, 不阻止更新
更新规则: 同一 key 内容替换, 不创建新条目
```

| 实体类型 | 唯一 Key | 更新策略 | 去重规则 | 保护 |
|:---------|:---------|:---------|:---------|:-----|
| **项目方案** | `plan:<项目名>` | 原地替换(旧→新) | 同一 key 不重复 | ✅ |
| **任务进度** | `progress:<编号>` | 追加(每时间戳一条) | 同 key+同日不重复 | ✅ |
| **执行日志** | `exec:<会话ID>:<轮次>` | 追加(每个操作一条) | 同会话+同命令不重复 | session内 |
| **用户纠正** | `correction:<内容hash>` | 不更新, 全部保留 | 同 hash 不重复 | ✅永久 |
| **决策记录** | `decision:<内容hash>` | 不更新, 全部保留 | 同 hash 不重复 | ✅ |
| **已完成任务** | `completed:<编号>` | 一次性写入, 不更新 | 同 key 不重复 | 冷储 |
| **普通对话** | 无 | 抽屉压缩流转 | DedupEngine | ❌ |
