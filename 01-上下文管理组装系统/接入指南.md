## 二、集成合同（Contract）

### 2.1 组件依赖关系

```
drawer_engine.py        ← 零依赖，纯 Python stdlib
    │
    ├── memory_butler/__init__.py
    │   └── 依赖: call_aux_model_fn (函数引用, 见 2.2)
    │   └── 依赖: 知识库写入能力 (可选, 不实现则静默跳过)
    │
    └── context_assembler.py
        └── 依赖: 嵌入模型 API (可选, 不实现降级为全文搜索)
        └── 依赖: 知识库查询能力 (可选, 不实现则跳过向量搜索章节)
```

### 2.2 必须实现的接口

如果你要全盘接入，只需要实现 **一个函数**：

#### `call_aux_model(messages, temperature, max_tokens) -> str | None`

这是 Tier1 和 Tier2 唯一的外部依赖——调用辅助模型做摘要/分类。

```python
# 你只需要实现这么个函数：
def my_llm_call(messages: list[dict], temperature: float = 0.1, 
                max_tokens: int = 2048) -> str | None:
    """
    Args:
        messages: OpenAI 格式消息列表
                  [{"role": "system", "content": "..."},
                   {"role": "user", "content": "..."}]
        temperature: 生成温度 (摘要任务请用 0.1)
        max_tokens: 最大输出 token
    
    Returns:
        响应文本, 或 None (失败时返回 None, 系统会静默降级)
    """
    # 示例: 调 GLM-4-Flash (免费)
    response = requests.post(
        "https://open.bigmodel.cn/api/paas/v4/chat/completions",
        headers={"Authorization": f"Bearer {os.environ['ZHIPU_API_KEY']}"},
        json={
            "model": "GLM-4-Flash",
            "messages": messages,
            "temperature": temperature,
            "max_tokens": max_tokens,
        }
    )
    if response.status_code == 200:
        return response.json()["choices"][0]["message"]["content"]
    return None
```

**为什么这么设计？** 通过函数引用注入而不是硬编码，让你可以：
- 用任何模型（GPT-4o mini / Claude Haiku / 本地模型）
- 用任何 API（OpenAI 格式 / 自建 / Ollama）
- 随时切换，不影响核心逻辑

### 2.3 可选实现的接口

#### 知识库接口（PG）

Tier2 (memory-butler) 和 Tier3 (context-assembler) 依赖知识库持久化。代码中默认用 `psql` subprocess 连 PostgreSQL。你可以替换为：

| 组件 | 需要替换的函数 | 返回值说明 |
|:-----|:--------------|:-----------|
| 渐进摘要 | `_pg_insert_entry(title, content, category, tags)` | 返回 entry_id 或 None |
| 历史检查 | `_pg_search_tags(tag_prefix)` | 返回 list[dict] |
| 向量搜索 | `_vec_search(query)` | 返回 list[{id, title, snippet, dist}] |
| 全文搜索 | `_ft_search(query)` | 返回 list[{id, title, snippet}] |
| 摘要查询 | `_fetch_active_summaries(limit)` | 返回 list[{id, title, content}] |
| 日志查询 | `_fetch_recent_exec_logs(limit)` | 返回 list[{id, title, content}] |

这些函数的签名在 `context_assembler.py` 和 `memory_butler/__init__.py` 的文件级函数中定义。替换方式：

```python
# 在初始化时注入自定义实现
import context_assembler as ca
ca._vec_search = my_vector_search  # 替换函数引用
ca._pg_exec = my_db_query          # 替换数据库查询
```

### 2.4 框架集成点

如果你用的是 Agent 框架，需要在以下位置挂载：

| 框架 | 挂载点 | 做什么 |
|:-----|:-------|:-------|
| **Hermes Agent** | `plugins/context_engine/` | 实现 ContextEngine ABC |
| **LangChain** | `BaseChatMemory` 的自定义实现 | 在每次对话后调用`compress()` |
| **AutoGen** | `Agent` 的 `process_last_message()` | 在 agent 响应前组装上下文 |
| **自定义框架** | 每次 LLM 调用前 | 调用 `assemble_context()` 生成精炼系统消息 |

**最小挂载代码（伪代码）：**

```python
# 你的 Agent 框架中
from drawer_engine import DrawerStack, NoiseFilter, ProtectionDetector
from context_assembler import assemble_context

class MyAgent:
    def __init__(self):
        self.drawer = DrawerStack(capacity=3)
        self.noise = NoiseFilter()
        self.protector = ProtectionDetector()
        self.round = 0
    
    def on_user_message(self, msg: str):
        # 1. 噪音过滤
        if self.noise.is_noise(msg):
            return  # 不计轮数
        
        # 2. 保护检测
        protect_info = self.protector.detect(msg)
        
        # 3. 推入抽屉
        self.drawer.push({
            "role": "user",
            "content": msg,
            "_protected": protect_info["protected"]
        })
        self.round += 1
        
        # 4. 检查抽屉满
        while self.drawer.is_top_full:
            items = self.drawer.pop_top()
            summary = call_aux_model([...])  # 你的 LLM 调用
            self.drawer.push_summary({"role": "system", "content": summary})
    
    def prepare_context(self, user_msg: str) -> str:
        """在每次 LLM 调用前调用"""
        items = self.drawer.get_context_items()
        return assemble_context(items, user_message=user_msg)
```

## 三、三种集成模式

### 模式 A: 紧耦合（像 Hermes Agent 一样）

框架直接管理抽屉生命周期。

```
优点: 控制力强, 性能好
缺点: 框架和抽屉引擎耦合在一起
适用: 你拥有整个框架
```

```python
# 框架的每一轮对话中
def process_turn(user_message):
    # 1. 过抽屉管线
    compressor.on_user_message(user_message)
    
    # 2. 组装上下文
    context = compressor.prepare_context(user_message)
    
    # 3. 调用 LLM
    response = llm.chat(context + user_message)
    
    return response
```

### 模式 B: 事件驱动

抽屉引擎作为独立服务，通过事件总线通信。

```
优点: 解耦, 可替换
缺点: 延迟稍高
适用: 微服务架构
```

```python
# 事件: "new_user_message"
def on_new_message(event):
    drawer.push(event.message)
    if drawer.is_top_full:
        emit("drawer_full", {"level": drawer.current_level})

# 事件: "drawer_full"
def on_drawer_full(event):
    items = drawer.pop_top()
    summary = call_aux_model(summarize_prompt(items))
    drawer.push_summary(summary)
    emit("context_updated", {"context": drawer.get_context_items()})
```

### 模式 C: 中间件

作为 LLM 调用链的中间件层。

```
优点: 无侵入, 即插即用
缺点: 对中间件框架有依赖
适用: 已有中间件架构
```

```python
class DrawerMiddleware:
    def before_llm_call(self, messages, user_message):
        # 在调用 LLM 前注入压缩上下文
        context = assemble_context(self.drawer.get_context_items(), user_message)
        messages.insert(0, {"role": "system", "content": context})
        return messages
    
    def after_llm_call(self, messages, response):
        # 在 LLM 响应后压入用户消息
        last_user_msg = [m for m in messages if m["role"] == "user"][-1]
        self.push_to_drawer(last_user_msg)
        return response
```

## 四、最小集成示例（50 行）

以下是用纯 Python 接入 Tier1 抽屉引擎的最简代码：

```python
"""minimal_integration.py — 最小接入示例"""
import sys
sys.path.append("/path/to/round-compressor")

from drawer_engine import (
    DrawerStack, NoiseFilter, ProtectionDetector,
    UniqueKeyIndex, TemperatureIndex, call_aux_model
)

class MinimalCompressor:
    """最小抽屉级联压缩器"""
    
    def __init__(self, llm_call_fn):
        self.drawer = DrawerStack(capacity=3)
        self.noise = NoiseFilter()
        self.protector = ProtectionDetector()
        self.keys = UniqueKeyIndex()
        self.temperature = TemperatureIndex()
        self.llm_call = llm_call_fn
        self.round = 0
    
    def feed(self, user_message: str):
        """每轮用户消息后调用"""
        # 1. 噪音过滤
        if self.noise.is_noise(user_message):
            return
        
        # 2. 保护检测
        info = self.protector.detect(user_message)
        self.keys.tick()
        if info["key"]:
            verdict = self.keys.check(info["key"], user_message, info["protection_type"])
            if verdict["action"] == "skip":
                return
            self.keys.register(info["key"], user_message, info["protection_type"])
        
        # 3. 推入抽屉
        self.drawer.push({
            "role": "user",
            "content": user_message,
            "_protected": info["protected"],
        })
        
        # 4. 温度命中
        self.temperature.hit(info["key"] or user_message[:40], user_message, info.get("importance_bonus", 0))
        self.round += 1
        
        # 5. 抽屉满→压缩
        while self.drawer.is_top_full:
            items = self.drawer.pop_top()
            protected = [m for m in items if m.get("_protected")]
            compressible = [m for m in items if not m.get("_protected")]
            
            if compressible:
                text = "\n".join(str(m.get("content","")) for m in compressible)
                summary = self.llm_call([
                    {"role": "system", "content": "压缩以下对话为 200 tok 摘要"},
                    {"role": "user", "content": text},
                ])
                self.drawer.push_summary({"role": "system", "content": f"[摘要] {summary}"})
            
            for m in protected:
                self.drawer.push_to_head(m)
    
    def get_context(self) -> list:
        """获取当前上下文"""
        return self.drawer.get_context_items()

# 使用示例
def my_llm(messages):
    """你自己的 LLM 调用函数"""
    # import requests
    # return requests.post(...)
    return "模拟摘要输出"

comp = MinimalCompressor(my_llm)
comp.feed("你好")
comp.feed("我们来设计一个上下文管理系统")
comp.feed("核心用抽屉级联，N=3")
print(comp.get_context())  # 3条原始消息
comp.feed("TFC-155: 抽屉容量设为4")
# 抽屉满了, 前3条压缩成1条摘要
print(comp.get_context())  # 1条摘要 + 1条原始
```

## 六、已知接入陷阱

1. **`call_aux_model` 必须是关键词参数调用** — 内部调用方式为 `fn(messages=[...], temperature=0.1, max_tokens=512)`，不是位置参数
2. **`UniqueKeyIndex.check()` 返回 dict，不是 bool** — `result["action"]` 是 `"pass"|"skip"|"replace"|"append"`
3. **`NoiseFilter.is_noise()` 不区分 user/assistant** — 只检查文本内容，如果要只过滤 user 消息，在调用前判断 role
4. **保护条目放回头部 (`push_to_head`)** — 不会占用抽屉满的判定，但会出现在 `get_context_items()` 中
5. **`get_context_items()` 返回倒序** — 当前层全量 + 下层最新一条（从顶层到底层）
6. **辅助模型全部失败时静默降级** — `call_aux_model` 返回 None，摘要降级为关键词提取
