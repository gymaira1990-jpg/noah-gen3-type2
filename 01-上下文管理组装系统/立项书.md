## 一、为什么做

### 1.1 背景

诺亚原型机 0101 型（原铸诺亚）在长期运行中积累了一套完整的上下文管理系统——从抽屉级联压缩引擎到记忆管家到上下文组装器。这套系统在实际生产中验证了：

- 38.5:1 的上下文压缩比，无悬崖失忆
- 100% 免费模型完成所有压缩任务
- 7 类保护机制确保关键信息不丢失
- 跨会话上下文恢复

但原铸诺亚的代码是深度耦合在特定 Agent 框架（Hermes Agent）中的，无法直接复用到其他场景。

### 1.2 目标

将上下文管理能力从原铸诺亚中解耦，设计为 **与框架无关的通用型上下文管理组装系统**，满足以下场景：

- 任何 LLM Agent 框架（LangChain / AutoGen / 自定义）
- 任何基础模型（GPT / Claude / DeepSeek / 开源模型）
- 任何部署环境（本地 / 云 / 边缘设备）

### 1.3 核心命题

> 如何让一个大语言模型在无限长的对话中，永远：
> 1. 记得刚刚做过什么（执行日志）
> 2. 记得用户纠正过什么（纠正保护）
> 3. 记得正在做什么（活跃项目追踪）
> 4. 记得做过的决策（决策存档）
> 5. 不记得寒喧废话（噪音过滤）
> 6. 不重复犯错（重复检测）
> 7. 花最少的钱（免费模型压缩）

## 二、做什么

### 2.1 产出物

1. **上下文引擎 SDK**：与框架无关的 Python 包，提供三层级级联管线
2. **集成适配器**：Hermes Agent / LangChain / AutoGen 等框架的集成示例
3. **技术说明书**：本仓库 `01-上下文管理组装系统/` 下的完整文档

### 2.2 范围

| 模块 | 包含 | 不包含 |
|:-----|:-----|:-------|
| Tier1 抽屉引擎 | 噪声过滤 / 保护识别 / Key管理 / 去重 / 抽屉级联 / 温度系统 | 具体 LLM 调用 |
| Tier2 记忆管家 | 渐进摘要 / 执行日志 / 冷储 / 重复检测 | 具体记忆存储实现 |
| Tier3 上下文组装器 | 组装公式 / 向量搜索 / 性能指标 | 具体 embedding 模型 |
| 辅助模型调度 | 多链调度 / 降级策略 / 免费路由 | 具体 API 调用 |

### 2.3 非目标

- 不做记忆存储引擎本身（依赖外部向量库/数据库）
- 不做 Agent 框架（提供集成适配器即可）
- 不做 UI/可视化管理界面

## 三、怎么做

### 3.1 设计原则

1. **零幻觉优先**：不依赖 LLM 做关键判断，机械规则兜底
2. **渐进非暴力**：每次只压缩满的抽屉，不一次性全量压缩
3. **保护先于压缩**：关键信息永远不能被压缩丢失
4. **免费优先**：能用正则不做 LLM，能用免费模型不用付费
5. **一劳永逸**：修复必须是代码锁死的永久方案

### 3.2 技术栈

| 层 | 技术 | 说明 |
|:---|:-----|:-----|
| 核心 | Python 3.11+ | 类型注解, dataclass |
| 向量 | pgvector | PostgreSQL 向量扩展 |
| 嵌入 | 任意 embedding 模型 | slot 设计, 可插拔 |
| 摘要 | GLM-4-Flash / Qwen3-8B | 免费路由链 |
| 框架 | Hermes Agent | 主集成目标 |

### 3.3 开发阶段

| 阶段 | 内容 | 产出 |
|:-----|:-----|:-----|
| P0 | 架构设计 + API 定义 | 本文档 + 接口规范 |
| P1 | Tier1 抽屉引擎核心 | 解耦的 drawer_engine.py |
| P2 | Tier2 记忆管家 | 解耦的 memory-butler |
| P3 | Tier3 上下文组装器 | 解耦的 context-assembler |
| P4 | Agent 适配器 | Hermes/LangChain 集成 |
| P5 | 文档 + 测试 + 示例 | 完整 SDK |
