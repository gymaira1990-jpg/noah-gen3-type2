# 方案设计 02：降智防御体系

> 所属模块: 05-对话融合核心·语言沟通引擎
> 版本: v0.1 (方案)
> 日期: 2026-05-23

---

## 1. 问题定义

「降智」在诺亚语境中的定义：**同一个问题，压缩后的回答质量显著低于压缩前。**

当前 Hermes 模式下降智的三种根因：

| 根因 | 表现 | Hermes 的应对 | 我们的方案 |
|:-----|:-----|:-------------|:-----------|
| **信息丢失** | 摘要丢掉了关键决策/文件内容/工具结果 | 无（线性压缩，不可控） | 结构化事实摘要 + 保护标记 |
| **叙事污染** | 自由叙事摘要编造了不存在的内容 | 无（依赖模型诚实） | 结构化格式约束，禁止自由叙事 |
| **上下文冲突** | 压缩后的两个片段互相矛盾 | 无（不检查一致性） | 唯一键排重 + 版本冲突检测 |

## 2. 防御体系总览

```
降智防御 = 事前保护 + 事中精炼 + 事后验证

事前保护（部署期）
├── __HERMES_SOUL_PROTECTED__ 硬编码标记
├── [PROTECTED:] 决策保护前缀
├── 用户纠正自动保护
└── 工具结果保护区 (protect_last_n)

事中精炼（每轮对话）
├── 结构化事实摘要（非自由叙事）
├── 热度保护（高频信息自动升温）
├── 唯一键排重（同一TFC卡不同状态不冲突）
└── OA工单瓶颈（可选，强制精炼）

事后验证（定期/触发）
├── 摘要-原文一致性检查（抽样）
├── 工具结果完整率检查
└── 用户纠正保留率检查
```

## 3. 结构化事实摘要（核心防御）

### 3.1 摘要格式

不允许自由叙事。摘要必须以固定结构化格式生成：

```markdown
## 活跃目标
- 正在做什么: [用户当前正在处理的TFC/任务]
- 当前步骤: [进度描述]

## 已做决策
- [决策时间] [决策内容] {引用来源}

## 文件变更
- [文件路径] → [变更类型: 创建/修改/删除] [变更摘要]

## TFC关联
- TFC-NNN: [状态] [最后操作]

## 用户纠正记录
- [纠正内容] {保留原始上下文}

## 执行日志
- [时间] [操作描述] [结果]
```

### 3.2 格式约束规则

| 规则 | 强制程度 | 违反后果 |
|:-----|:-------:|:---------|
| 每条摘要必须包含至少一个非空的章节 | 🔴 必须 | 不能压缩 |
| 「已做决策」中的每个条目必须有原文引用 | 🔴 必须 | 降智风险标记 |
| 「活跃目标」最多3条 | 🟡 建议 | 超出的合并 |
| 「用户纠正记录」中的条目永不被删除 | 🔴 必须 | 热度锁定 |
| 禁止出现「用户表示」「用户提到」等模糊主语 | 🔴 必须 | 格式错误 |

### 3.3 实现

结构化摘要由模块01的 Tier2 MemoryButler 生成，其 `progressive_summarize()` 方法已支持格式约束输出的 prompt 模板。本模块只需传入正确的格式模板，无需改动 Tier2 代码。

## 4. 热度保护机制

### 4.1 热度模型

每条消息/事实有 `heat` 值（0.0~1.0），每轮对话更新：

```
heat_new = heat_old × 0.95 + boost
         ^              ^        ^
         衰减因子       衰减     增益

增益规则:
  +0.20  用户明确引用/追问同一话题
  +0.15  用户纠正了之前的内容
  +0.10  包含 TFC/NCP/PRJ 编号
  +0.05  普通对话（维持基线）
  -0.05  自动衰减（每轮）
  
阈值:
  heat ≥ 0.60  → 🔴 保护区（永不压缩）
  heat ≥ 0.30  → 🟡 摘要区（结构化摘要保留）
  heat < 0.30  → 🟢 可丢弃（噪音/寒喧）
```

### 4.2 热度锁定

用户纠正的内容自动锁定 `heat >= 0.80`，不衰减。

```python
if "纠正" in user_message or "不是" in user_message or "不对" in user_message:
    # 这条消息和相关的上条助理回复都锁定热度
    heat = max(heat, 0.80)
    decay_multiplier = 0.0  # 不衰减
```

## 5. 保护标记体系

| 标记 | 作用域 | 效果 |
|:-----|:------|:-----|
| `__HERMES_SOUL_PROTECTED__` | 全局 | 整条消息永不被压缩/摘要/删除 |
| `[PROTECTED:]` | 段落 | 该段落及后续内容受保护 |
| `[PROTECTED:决策]` | 决策 | 该决策永不被摘要合并 |

保护标记在 `compress()` 入口由 ProtectionDetector 识别，标记的消息跳过所有去噪/去重/摘要步骤，直接保留在输出中。

## 6. 唯一键排重（防止上下文冲突）

### 6.1 问题

同一 TFC 卡在不同时间有不同状态。如果两条摘要都提到 TFC-155，一条说「方案设计中」，一条说「已完成」，传统去重会保留一条，导致信息冲突。

### 6.2 方案

```python
UniqueKeyIndex.KEY_FIELDS = ["role", "tool_call_id", "id", "tfc_id"]

# TFC-155 不同状态的两次引用:
#   key = ("assistant", None, None, "TFC-155") 
#   两次 key 相同, version 不同 → 保留较新的
#   如果不含 TFC-ID:
#   key = ("assistant", "call_xxx", "msg_123", None)
#   完全不同的 key → 两条都保留
```

## 7. 事后验证

### 7.1 运行时检测

每次压缩后，检查以下指标：

```python
verification_result = {
    "compression_ratio": 0.75,          # 压缩比
    "info_loss_warning": None,           # 信息丢失警告
    "tool_result_preserved": 1.0,        # 工具结果保留率
    "decision_preserved": 1.0,           # 决策保留率
    "correction_preserved": 1.0,         # 纠正保留率
    "suspected_hallucination": False,    # 摘要幻觉标记
}
```

如果 `tool_result_preserved < 0.9` 或 `correction_preserved < 0.9`，触发降级（不压缩，用原始消息）。

### 7.2 定期审计

每 100 轮对话做一次全量审计：
- 随机抽取 5 个压缩前后的对照
- 检查摘要中的事实是否有原文支撑
- 检查工具调用结果是否完整保留

## 8. 降智度量标准

本模块用以下量化指标衡量「是否降智」：

| 指标 | 正常 | 警告 | 降智 |
|:-----|:----:|:----:|:----:|
| 工具结果保留率 | ≥95% | 80-95% | <80% |
| 决策保留率 | ≥90% | 70-90% | <70% |
| 纠正保留率 | 100% | — | <100% |
| 摘要幻觉率 | 0% | — | >0% |
| 用户反馈负面率 | <5% | 5-15% | >15% |

任何指标进入「降智」区间 → 自动关闭 05 模块压缩，回退到 Hermes 原生模式。
