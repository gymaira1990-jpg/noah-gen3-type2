# 方案设计 05：降级与保底设计

> 所属模块: 05-对话融合核心·语言沟通引擎
> 版本: v0.1 (方案)
> 日期: 2026-05-23

---

## 1. 核心原则

**03 模块出问题 = Hermes 原生接管，用户零感知。**

Hermes 的对话循环保持不变，永远作为保底路径。05 模块是一个「可选的智能上下文层」——它在就在，不在也不影响 Hermes 正常工作。

## 2. 降级模型

```
用户消息
   │
   ▼
┌──────────────────────────────┐
│  05模块健康检查                │
│                              │
│  🟢 健康 → 走诺亚对话循环      │
│  🟡 警告 → 走诺亚但关闭压缩    │
│  🔴 故障 → 透明回退 Hermes    │
└──────────────────────────────┘
```

### 2.1 健康指标

```python
@dataclass
class EngineHealth:
    status: Literal["green", "yellow", "red"]
    
    # 核心指标
    context_assembly_ok: bool        # 上下文组装正常
    llm_communicator_ok: bool        # LLM调用正常
    tool_bridge_ok: bool             # 工具桥接正常
    persistence_ok: bool             # 持久化正常
    memory_sync_ok: bool             # 记忆同步正常
    
    # 统计指标
    last_error: str | None           # 最后一条错误
    error_count_1h: int              # 过去1小时错误数
    avg_latency_ms: float            # 平均延迟
    degradation_score: float         # 降智评分 (0=完美, 1=完全降智)
```

### 2.2 降级触发条件

| 条件 | 级别 | 行为 |
|:-----|:----:|:-----|
| 上下文组装返回 None | 🔴 | 跳过05，走Hermes |
| LLM 调用连续失败 3 次 | 🔴 | 跳过05，走Hermes |
| 工具桥接连续失败 5 次 | 🟡 | 关闭工具调用，仅文本对话 |
| 持久化写入失败 | 🟡 | 降级到内存模式，日志告警 |
| 降智评分 > 0.3 | 🟡 | 关闭05压缩，走Hermes压缩 |
| 模块01/02 接口异常 | 🔴 | 跳过对应模块，降级到Hermes |

## 3. 降级实现

### 3.1 网关模式（推荐）

05 模块作为 Hermes Gateway 和 Hermes 对话循环之间的网关层：

```python
class ConversationGateway:
    """
    对话网关：优先走05模块，故障时透明回退到Hermes。
    """
    
    async def process_message(
        self,
        user_message: str,
        session_id: str,
    ) -> AsyncIterator[dict]:
        """处理用户消息，优先05，回退Hermes"""
        
        # 检查05模块健康
        if self.noah_engine.health.status == "green":
            # 走05模块对话循环
            try:
                async for event in self.noah_engine.process(user_message):
                    yield event
                return
            except Exception as e:
                logger.error(f"Noah engine failed: {e}, falling back to Hermes")
                # 标记降级
                self._record_fallback(session_id, "noah_engine", str(e))
                # 不return，继续走Hermes路径
```

### 3.2 Man-in-the-middle 模式（Phase 1 推荐）

```
Hermes 正常跑对话
     ↑
05 模块作为 MITM 层：
  - 监听 Hermes 的输入和输出
  - 同步运行自己的上下文组装
  - 比较两者质量（不干预 Hermes 的输出）
  - 收集指标
```

MITM 模式的安全优势：
- Hermes 完全不受影响（05 只看不碰）
- 可以积累真实对话数据做对比测试
- 发现 05 输出质量高于 Hermes 时才切换

## 4. 恢复机制

05 模块故障后，后台自动尝试恢复：

```python
class HealthRecovery:
    """自动恢复：故障后定期重试，成功时透明切回"""
    
    def __init__(self):
        self.retry_intervals = [30, 60, 120, 300]  # 秒
        self.retry_index = 0
        self.last_attempt = None
    
    async def try_recovery(self) -> bool:
        """尝试恢复05模块"""
        now = time.time()
        if self.last_attempt and now - self.last_attempt < self.retry_intervals[self.retry_index]:
            return False  # 还没到重试时间
        
        self.last_attempt = now
        try:
            # 执行健康检查
            health = await self.noah_engine.check_health()
            if health.status == "green":
                self.retry_index = 0  # 重置重试间隔
                logger.info("Noah engine recovered, switching back")
                return True
        except:
            pass
        
        # 递增重试间隔（最多到300s）
        self.retry_index = min(self.retry_index + 1, len(self.retry_intervals) - 1)
        return False
```

## 5. 测试验证

| 场景 | 预期行为 | 验证方法 |
|:-----|:---------|:---------|
| 05模块进程被kill | Hermes 透明接管，用户无感知 | kill 05进程后继续发消息 |
| 上下文组装超时(>10s) | 降级到 Hermes 压缩 | 模拟模块01慢响应 |
| LLM 调用返回乱码 | 重试 3 次后降级 | 设置无效 provider URL |
| 持久化 PG 断开 | 内存模式 + 日志告警 | 停止 PG 服务 |
| 模块01 返回空数据 | 跳过上下文组装，用原始消息 | 模拟空返回值 |
