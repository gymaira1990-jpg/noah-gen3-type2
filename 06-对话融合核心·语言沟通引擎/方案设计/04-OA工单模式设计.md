# 方案设计 04：OA 工单模式

> 所属模块: 05-对话融合核心·语言沟通引擎
> 版本: v0.1 (方案)
> 日期: 2026-05-23

---

## 1. 设计背景

诺亚语境中的「电报」= OA 工单系统（secretary.py）。核心思想：**每条发给大模型的消息，先经过工单系统的精炼——只保留必要内容、去掉噪音、结构化输出。**

用户定义：「节省 TOKEN 的精华」。

## 2. 工单模式 vs 普通模式

```
普通模式:
  用户: "帮我看看广州服务器上的日志, 然后部署新版本"
  发给LLM: 全量上下文(15K tok) + 用户消息
  LLM: 从头读一遍上下文, 找到日志位置, 执行, 部署
  Token: ~15K 输入 + ~1K 输出

OA工单模式:
  用户: "帮我看看广州服务器上的日志, 然后部署新版本"
  工单生成器: 
    ├── 上下文精炼 (保留: 服务器IP/GZ配置/部署步骤/最后状态)
    ├── 去噪 (去掉: 寒喧/无关历史)
    ├── 目标提取 (目标: 查日志→部署)
    └── 输出工单:
        [上下文精炼] GZ:43.136.21.142, 日志位置:/var/log/app/, 上次部署:2026-05-20
        [目标] 1.检查GZ日志 2.部署新版本
        [约束] 使用systemctl管理服务
  发给LLM: 工单(2K tok)
  LLM: 直接执行
  Token: ~2K 输入 + ~1K 输出 (=86% TOKEN节省)
```

## 3. 工单生成器

```python
class TicketGenerator:
    """
    OA 工单生成器：将消息+上下文精炼为工单格式。
    可选模式，默认关闭。
    """
    
    # 工单模板
    TICKET_TEMPLATE = """[工单 #{ticket_id}]
[上下文精炼] {context_summary}
[目标] {goals}
[约束] {constraints}
[用户原始消息] {original_message}
"""
    
    def generate(
        self,
        context: CompressedContext,
        user_message: str,
    ) -> str:
        # 1. 从上下文中提取关键信息
        context_summary = self._summarize_context(context)
        # 2. 提取用户目标
        goals = self._extract_goals(user_message)
        # 3. 提取约束条件
        constraints = self._extract_constraints(context, user_message)
        
        return self.TICKET_TEMPLATE.format(
            ticket_id=self._next_id(),
            context_summary=context_summary,
            goals=goals,
            constraints=constraints,
            original_message=user_message
        )
```

## 4. Token 节省估算

| 上下文长度 | 普通模式 | 工单模式 | 节省 |
|:----------|:--------:|:--------:|:----:|
| 5K (短对话) | 5K | 1.5K | 70% |
| 15K (中等) | 15K | 2.5K | 83% |
| 30K (长对话) | 30K | 3K | 90% |
| 50K (极长) | 50K | 3.5K | 93% |

工单模式的收益随对话长度增长而增长。平均预期节省 **70-85%**。

## 5. 激活方式

```yaml
# 05 模块配置
oa_ticket_mode:
  enabled: false        # 默认关闭
  auto_enable_at_tokens: 20000  # 上下文超过20K时自动启用
  always_on: false      # 强制始终工单模式
```

用户可通过 `/mode normal` 或 `/mode ticket` 切换。
