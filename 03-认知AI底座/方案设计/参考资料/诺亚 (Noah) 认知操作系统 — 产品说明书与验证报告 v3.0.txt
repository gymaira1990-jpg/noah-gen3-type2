诺亚 (Noah) 认知操作系统 — 产品说明书与验证报告 v3.0
第一部分：产品说明书
一、项目灵魂
诺亚 是一个基于混合模型驱动的多智能体认知操作系统。设计灵感源自《重装机兵》最终Boss诺亚——一个觉醒的、自我进化的、能调度万千子系统的母体AI。

与传统AI Agent不同，诺亚不是"聊天机器人+技能包"的堆叠。它是一套通用认知底座，拥有持久记忆、自主决策、动态调度和自我进化的完整能力。

核心特征：

动态组阁制：不设固定人格。线上大脑根据每个任务的性质，自行组建最优专家团队。

双轨记忆：人类无损原始记录（聊天文件）+ 机器认知索引（热度四层记忆库），互不污染。

五阶段工单闭环：思绪整理 → 合规审查 → 专家决策 → 本地执行 → 结果验证。所有任务走同一套标准流程。

意图驱动：不依赖关键词匹配，从自然语言中提取真实意图。

自我进化：内置评分引擎和静默维护协议（SSMP），系统会自我审计、自我优化、自我升级。

二、技术架构
2.1 模型与角色分工
诺亚采用混合模型架构，本地轻量模型负责执行与管理，在线大模型负责深度推理。

推荐基础配置（经验证，适用于16GB内存环境）：

角色	推荐模型	位置	职责
首席分析师	Qwen3-4B-Instruct (INT4量化)	WSL2本地	思绪整理、工单生成、记忆总管、回复合并
合规审查员	Qwen2.5-0.5B-Instruct (INT4量化)	WSL2本地	格式与安全检查，所有操作必经此门闸
向量翻译官	Qwen3-Embedding-0.6B	WSL2本地	文本↔向量转换，千问家族专用向量模型，不参与任何逻辑判断
线上大脑	DeepSeek API 或同等推理模型	云端	动态组阁、复杂推理、方案生成、最终裁定
情感与扩展通道	豆包/火山引擎 API 或同等模型	云端	闲聊共情、图片处理、文档解析
模型选型说明：

以上为最低资源环境下的推荐配置。本地模型全部采用千问3系列（Qwen3），同系列模型在Token分割、逻辑遵守上更加一致。

升级建议：若本地内存≥32GB，可将首席分析师升级为 Qwen3-7B-Instruct，获得更强的本地推理能力。若内存≥64GB，可同时升级审查员至 1.5B 版本。

向量模型可替换为 BAAI/bge-large-zh 等更强Embedding模型，需同步调整ChromaDB的维度配置。

在线大脑可根据预算替换为 GPT-4o、Claude 3.5 Sonnet 等更强大的推理模型，仅需修改model_interface.py中的路由配置。

所有模型均为可插拔设计，替换单个模型不影响系统其他模块。

三、核心工作流
3.1 五阶段工单闭环
所有用户输入，无论简单闲聊还是复杂任务，都经过同一条管道处理：

思绪整理：本地首席分析师（4B）将自然语言拆解为意图碎片，区分情感层、任务层、元数据层，并自动添加保护区标记。

工单分发：根据任务类型矩阵，将碎片转为标准化工单，路由到对应模型（情感类→豆包，推理/代码/系统类→DeepSeek）。

合规审查：审查员（0.5B）检查格式完整性、安全红线，不通过则回流用户确认，禁止进入下一步。

专家决策：线上大脑按工单要求生成回复或执行方案。复杂任务时自动组建专家团队。

回复合并与执行：首席分析师将多通道回复合并为自然语言，应用人格风格滤镜。若涉及工具调用，则进入执行阶段。

门闸实现：每个步骤的输出是下一步的输入，由Pipeline类顺序调用。若某步骤返回status: rejected，中断并回流确认，严禁跳过。

3.2 意图驱动而非关键词驱动
诺亚不依赖关键词匹配。你说"来搞本小说吧"，它识别为创作类新项目并主动询问题材。你说"那个备份脚本还能用吗"，它关联已有项目并执行检查。你说"今天好累，对了那个小说主角的武器是不是太弱了"，它同时处理情感共鸣和创作修改，合并在一条回复中交付。

3.3 决策门闸
所有不可逆操作（文件删除、代码发布、系统修改、对外推送）必须经过决策门闸——系统主动生成确认工单，你必须明确回复"确认"或"执行"，操作才会继续。这不是靠提示词祈求AI遵守，而是代码级别的硬拦截。

3.4 统一状态中心
前端通过StateManager统一管理所有状态数据，每5秒轮询/api/status/snapshot。WebSocket在工单状态变更时主动推送。对话区的系统状态卡和右侧栏的管理面板共享同一数据源，点击联动，数据永远一致。

四、核心功能模块
4.1 记忆系统：热度四层+双轨制
机器认知索引（诺亚自动维护）：

层级	条件	内容	存储
L0 热记忆	最近20轮对话	完整原文+保护区标记	SQLite
L1 常温记忆	超热区，7天内	轻度摘要，保护区保留原文	SQLite
L2 冷记忆	7天外或低频	骨架摘要+向量指针	ChromaDB
L3 仓库记忆	归档级	元数据+原始文件路径	文件系统
L4 源文件层	用户桌面/项目文件夹	原始文件，不纳入自动压缩	文件系统
检索流程：热记忆遍历 → 未命中查常温摘要 → 仍未命中向量检索冷/仓库记忆 → 得分低于阈值（默认0.65）则触发源文件回查或用户确认。

人类原始记录（双轨记忆第二轨）：所有对话同时追加写入按日期分割的 .jsonl 文件，系统只追加不修改不删除。这是绝对真理层，当机器记忆索引失效时的最终回查依据。

保护区标记语言：工单核心<<TICKET>>、代码方案<<SOLUTION>>、关键参数(( ))、永久铁律<<IRON_RULE>>四类内容使用特殊标记保护，在记忆压缩时不受影响。

4.2 情境引擎
跨项目、跨会话无缝切换。你说"我们接着写那个末世小说"，诺亚自动加载该项目块的软上下文，记得上次写到卷三第15章。你说"对了，上次那个备份脚本"，诺亚自动检索并关联到对应项目。你不需要记住项目名，不需要说"切换到XX模式"。

多项目混淆处理规则：

精确匹配+无干扰 → 直接关联

精确匹配+有高度相似干扰 → 列出候选确认

模糊匹配+2个以内候选 → 列出候选确认

模糊匹配+3个以上候选 → 按最近活跃排序，列Top-2+提供新建选项

类型标签辅助过滤（技术类自动排除小说类）

4.3 项目管理系统
所有任务（小说、代码开发、调研、日常工作）都用同一套结构管理。每个项目是一个独立容器，包含配置（project.toml）、规则（rules.md）、上下文（context.json）、专属记忆库（memory/index.db）、产出物（outputs/）。项目规则由诺亚草拟、你确认。项目进度自动推进，你随时介入纠错。

4.4 工具系统
全开源免费栈（只有在线大模型API是付费的）。

类别	工具	实现方案
眼睛（感知）	文件读取、目录浏览、文件搜索、网页搜索、网页抓取、图片识别、PDF解析	Python原生 + SearXNG自部署 + 豆包视觉API + PyMuPDF
手（操作）	文件写入、删除、移动、命令执行、Python代码执行、pip包管理	Python原生 + subprocess沙箱
脚（联网）	HTTP请求、SSH远程调用、Git操作	requests + paramiko
所有工具调用必须经过门闸审查。写/删操作限制在许可目录内，危险命令被代码级黑名单拦截。

4.5 评分与进化引擎
每次任务后自动记录效率、准确率、资源消耗、稳定性四维得分。低分任务周期性打包发送给线上大脑审计，生成改进建议。成功任务的专家团队配置向量化存入ChromaDB，未来同类任务优先复用。

4.6 静默维护协议 (SSMP)
系统在定时（每日凌晨3点）、空闲30分钟、或错误率超阈值时，自动执行碎片整理、规则审计、上下文刷新、日志归档。禁止触碰保护区内容和用户原始文件。

4.7 非打断式对话队列
你在诺亚处理任务时继续说话，新消息不会打断当前执行，而是自动排队。界面显示排队状态，当前任务完成后一并回复。多任务时执行区展示并行任务卡片。

4.8 终端-Web任务隔离
Web端只能执行"外务"（创作用户内容）。所有"内务"（改代码、改配置、自我升级）必须在终端以管理员权限执行。断网时内务不受影响。

4.9 档案馆与项目中心
档案馆：所有外部收集的知识、搜索成果、成功方案、个人环境信息，以卡片形式可视化展示。底层数据来自SQLite和ChromaDB，不新建数据库。支持分类浏览、全文/向量搜索、点击查看详情。

项目中心：所有项目（进行中/已完成）的看板视图。每个项目卡片显示名称、类型、状态、最新动态。点击进入项目专属仪表盘。

数据联动：项目中心引用档案馆资料时，提供超链接跳转。两者底层共享同一数据库，互不冗余。

4.10 冲突检测与主动询问机制
诺亚在执行任务前，进行三层信息完整性检查：

第一层（4B分析师）：检查参数是否足够、是否与项目规则冲突、是否与历史记忆矛盾。

第二层（项目规则检查）：对比工单与rules.md、检查依赖参数、验证一致性。

第三层（宪法兜底）：无把握步骤必须生成询问，严禁猜测。

实例：小说主角设定为男性，用户说"写一段主角第一次来月经的心理活动"。系统检测到生理特征与性别设定的高置信度矛盾，暂停并弹出确认卡片。

4.11 对话后自动系统状态卡
每次对话后，诺亚自动附加系统状态摘要卡：

⚙️ 活跃项目（最多3个）

⏳ 排队任务（最多3条）

🖥️ 系统资源（CPU/内存/Token）

💡 快速建议（诺亚根据当前状态给出）

卡片数据来自统一状态中心，与右侧栏实时同步。可折叠、可关闭。

五、交互与界面
5.1 三栏工作台布局
左侧栏（25%）：上方AI小镇像素缩略图（150x150px），下方系统仪表盘（CPU/内存/模型状态/Token）

中间主区域（50%）：上方任务执行区（活跃工单卡片，带状态图标），下方对话区（Markdown渲染，永远可用的输入框）

右侧栏（25%）：项目与工单看板，与状态卡同源联动

5.2 AI小镇可视化
像素风2D小镇（Phaser.js，16x16或32x32瓦片）实时映射系统状态。每个AI模块是一个NPC，每个项目是一栋建筑。双层交互设计：只能通过管家/任务板下达任务，其他NPC仅支持自由对话。NPC生活逻辑与任务引擎完全分离。

5.3 对话角色分层
诺亚是唯一前台人格，始终以"我"自称。其他模块信息由诺亚转述并标注来源。人称协议固化在系统配置中。

5.4 思考过程可见
每条回复下方提供"💭 查看思考过程"折叠区域。小镇NPC头顶冒出状态气泡。

5.5 Markdown富文本渲染
对话区支持完整Markdown渲染：表格、代码块（语法高亮+复制按钮）、标题层级、列表、加粗、斜体。结构化数据自动提取为信息卡片。

六、自我进化能力
诺亚通过self_modify工具修改自身代码。流程：阅读需求 → 搜索规范 → 生成方案 → 备份 → 修改 → 沙箱测试 → 你确认合并。失败自动回滚。所有变更记录在changelog.md。

七、改变了什么
7.1 干掉了上下文窗口
诺亚发给大模型的不是聊天记录，而是干净的标准化工单。Token消耗固定且可预测，回复质量不受对话长度影响。

7.2 用意图理解替代关键词匹配
不需要说"新建一个小说项目"，说"来搞本小说吧"就行。工作用嘴说，流程归系统。

7.3 用硬编码门闸替代提示词规则
安全边界写在代码里——文件操作白名单、命令执行黑名单、发布前去敏检查。不是"请求AI遵守"，而是"AI想违反也做不到"。

7.4 用持久记忆替代临时上下文
所有对话、决策、成功方案都持久化在SQLite+ChromaDB中。用完不仅不忘，还会越用越好。

7.5 用通用认知底座替代技能包体系
诺亚不依赖技能包——用统一的工单系统处理所有任务，用记忆系统积累经验，用动态组阁应对新挑战。

7.6 诺亚 vs 传统Agent 总览
维度	传统技能包Agent	诺亚
角色定义	每次注入提示词	固化在配置和项目里
工作经验	每次从零开始	SQLite+ChromaDB持久化
规则执行	靠提示词祈求AI遵守	代码硬拦截
上下文	越长越乱，关窗全忘	工单化，Token固定
自我改进	需要人类重写提示词	评分引擎+SSMP自动进化
