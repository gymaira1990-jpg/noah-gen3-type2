# 03 · 认知AI底座 —— 方案总结

> **血统**: 原铸诺亚(noah-prime)数万轮实战萃取 + 诺亚生命计划设计资产 + 数字AI基座v3.0架构
> **状态**: 📄 方案设计 | **版本**: v1.0 | **日期**: 2026-05-22

---

## 一、核心定位

**认知AI底座**是诺亚三代·二型的"大脑中枢"——一个通用、可扩展的个人AI智能体核心系统，提供：
- 大模型统一路由与降级链
- 工具统一管理与MCP接入
- 认知记忆底座（四库记忆+热度流转）
- 电报/回复单协议（TEL/MAIL）——杜绝幻觉的架构级保障
- STC自我进化闭环
- 统一资源注册与全生命周期管理

**核心设计哲学**：一切皆资源，一切需注册；架构强制而非提示词恳求。

## 三、核心技术模块

### M1 · API管理模块（模型统一路由）

**设计要点**：
- **唯一的AI能力提供方**：所有需要AI模型的模块必须通过此模块调用，不直接访问模型API
- **一个模型一个专属连接器**：为每个模型深度定制参数、电报风格和解析方式
- **统一调用日志**：记录调用者、参数、结果、成本、质量评分

**连接器基类**：
```python
class BaseModelConnector(ABC):
    def __init__(self, model_id, client, metrics): ...
    def build_tel(self, task, facts, context) -> str: ...    # 定制电报格式
    def build_request_params(self, tel) -> dict: ...          # 定制API请求参数
    def parse_response(self, raw_response) -> dict: ...       # 解析回复单
    def record_call(self, success, latency_ms, tokens): ...   # 更新热度指标
```

**智能路由与降级链**：
```
路由决策：用户指定 → 场景默认 → 意图分类(复杂→API/简单→本地) → 热度排序
降级链：DeepSeek Chat(主) → 豆包Lite(备用) → 豆包Pro(强力后备) → 本地Qwen(兜底)
```

**统一调用接口**：
```python
class APIGateway:
    async def call(self, request: APIRequest) -> APIResponse:
        # 1. 记录调用开始 → 2. 路由选择模型 → 3. 构建请求并发送
        # 4. 记录结果(延迟/Token/成本) → 5. 更新模型热度 → 6. 返回MAIL
```

### M2 · 工具管理模块（MCP兼容）

**设计要点**：
- **工具的唯一调用入口**：所有模块通过 `/gateway/tool` 调用工具
- **标准化接入**：内置MCP协议支持，非MCP工具通过适配连接器
- **完整生命周期**：记录参数/结果/延迟，用于优化选择

**工具连接器基类**：
```python
class BaseToolConnector(ABC):
    async def execute(self, params) -> ToolResult: ...    # 执行工具
    async def health_check(self) -> bool: ...              # 健康检查
    def get_capabilities(self) -> List[str]: ...           # 能力描述
    def get_parameters_schema(self) -> dict: ...           # 参数Schema
```

**工具标准结果格式**：
```python
@dataclass
class ToolResult:
    status: str        # SUCCESS / FAILED / TIMEOUT
    data: Any          # 核心数据
    metadata: dict     # 执行元数据（耗时、来源等）
    error: Optional[str]
```

**工具分类**：
- **信息获取（眼）**：WebSearch, LocalFileReader, DBQuery, 文档检索
- **输出表达（口）**：EmailSender, MessagePush, 交付物写入
- **操作执行（手）**：CodeExecutor(沙箱), TerminalCmd, FileWriter
- **系统交互（脚）**：BrowserAutomation, SSHClient, API调用
- **监听接收（耳）**：WebhookReceiver, RSSReader, 定时触发器

### M3 · 认知记忆底座

#### M3.1 四库记忆体系

| 记忆库 | 说明 | 管理规则 |
|:------|:-----|:--------|
| **档案馆** | 完整原始记录，不可篡改 | 允许重复，更新时新增版本，旧标记deprecated |
| **知识馆** | 经验证且可重用的知识(key-value) | 键唯一，更新版本递增，查询取最新活跃版本 |
| **常规记忆** | 工单/对话摘要/热度管理 | 按热度自动流转（热→常温→冷却→仓库） |
| **保密记忆** | 加密存储，需授权访问 | AES-256加密，不参与一般检索，访问日志审计 |

#### M3.2 双权重热度引擎

**热度公式**：
```python
heat = 0.6 * exp(-λ * hours_since_last_access) + 0.4 * (access_count / max_access_count)
```

**四级流转**：
- 🔥 热记忆 (heat ≥ 70)：内存缓存 + DB，即时检索
- 🌤️ 常温记忆 (30 ≤ heat < 70)：DB检索
- ❄️ 冷却记忆 (10 ≤ heat < 30)：压缩存储
- 🏚️ 仓库记忆 (heat < 10)：仅摘要+索引，90天宽限期后标记待销毁

#### M3.3 去重合并策略

| 库类型 | 去重阈值 | 策略 |
|:------|:--------|:-----|
| 档案馆 | 语义相似度>0.95 | 新增版本，旧版标记deprecated |
| 知识馆 | 同key | 版本号+1，直接更新 |
| 常规记忆 | 相似度>0.9 + 同类型 | 合并摘要，累加频次，取最大热度 |
| TEL/MAIL | 相似度>0.95 | 更新现有MAIL，增加occurrence_count |

#### M3.4 双DB索引引擎

- **PostgreSQL（真相库）**：完整内容 + 元数据 + 版本历史
- **pgvector（索引库）**：向量摘要 + 指针(truth_id, truth_table) + 热度层级 + 项目ID

**检索分层**：
```
1. 指定项目？→ 加载项目索引，限定范围
2. 热记忆全文搜索（PG）
3. 热记忆向量搜索（pgvector, 混合相似度: 文本0.7+标签0.3）
4. 常温记忆全文搜索（PG）
5. 冷却记忆向量搜索（pgvector）
6. 仓库记忆搜索（PG）
7. 工具模块补充（网络搜索等）
```

### M4 · 电报/回复单协议（TEL/MAIL）

TEL/MAIL协议是认知AI底座的核心通信协议，从架构层面杜绝AI幻觉。

**电报格式（TEL）**：发送给大模型的标准化任务描述
```xml
<TEL>
<CONTRACT>质检验收规则...</CONTRACT>
<TASK>任务描述</TASK>
<FACTS>已核实事实（多源验证后）</FACTS>
<REQUIREMENTS>格式/语气要求</REQUIREMENTS>
<REFERENCES>历史工单引用</REFERENCES>
<PROGRESS>当前进度</PROGRESS>
</TEL>
```

**回复单格式（MAIL）**：大模型返回的结构化响应
```json
{
  "status": "SUCCESS | NEED_MORE_INFO | FAILED",
  "result": "核心答案",
  "evidence": "逐项核查结果",
  "uncertainties": "不确定项或缺失信息",
  "suggestions": "改进建议"
}
```

**强制核实管道**：
```
用户输入 → 提取待核实事实点 → 多源检索(本地+工具)
  → 本地模型逐条核实 → 生成已核实FACTS → 组装TEL
  → 发送至API管理 → 接收MAIL → 本地仲裁校验
  → SUCCESS? → 归档记忆+返回结果
  → NEED_MORE_INFO? → 自动补充检索重试(最多2次)
```

### M5 · STC自我进化系统

**能力树**：按任务类型组织(STC节点)，每个节点包含：
- 电报模板（该类型任务的最佳TEL格式）
- 最佳参数（temperature/top_p等）
- 验证规则（SUCCESS判断标准）
- 成功率（历史成功率统计）

**经验提炼**：
- 定期分析历史TEL/MAIL，聚类成功模板
- 提取反模式（FAILED的常见原因）
- 自动生成改进版本并测试

**自主进化**：
- 检测频繁出现的知识缺口
- 自动生成探索性电报
- 调用工具和模型尝试解决
- 成功则固化为新的STC能力

### M6 · 统一资源注册中心

**核心设计原则**：一切皆资源，一切需注册

**资源生命周期**：
```python
active → deprecated → archived → deleted
```

- 删除前自动检查引用关系，存在依赖则阻止或级联处理
- 定期完整性检查，自动发现孤立资源（幽灵数据）

**核心表**：`resource_registry`（类型/状态/指针） + `resource_relations`（依赖/归属）
