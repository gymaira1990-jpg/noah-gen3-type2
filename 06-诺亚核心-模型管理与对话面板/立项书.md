## 一、为什么做

### 1.1 背景

当前 AI 开发者的日常工具链里有一块空白：

- **Ollama**（169k stars）只管本地模型，不管理云端 API，也没有 Web UI
- **Open WebUI**（132k stars）功能强大但必须 Docker，部署重
- **LM Studio** 是桌面应用，不支持 Web 访问
- **llama.cpp** 是推理引擎，不提供模型管理

我们每天都在管理多个模型——DeepSeek API、本地 llama.cpp、Ollama——但需要一个统一的地方来：

1. 查看所有模型的状态（在线/离线/延迟）
2. 监视系统资源（GPU/内存/CPU/磁盘）
3. 一键切换模型对话
4. 发现并添加新模型（Ollama / llama.cpp / HuggingFace）

### 1.2 灵感来源

从 P4 Router 的模型管理面板和原铸诺亚的 「DeepSeek Chat 对话页」生产实践中提取核心功能，去掉复杂的五层抽象，用最直接的实现方式：

> **单文件起步，零多余抽象。功能到了自然拆。**

### 1.3 目标

构建一个 **pip install 即跑的轻量模型管理与对话面板**，核心能力：

| 能力 | 说明 |
|:----|:-----|
| **统一模型管理** | 同时管理云端 API 模型和本地（Ollama/llama.cpp）模型 |
| **实时状态监控** | GPU 温度/显存、CPU 负载、内存/磁盘/Swap |
| **DeepSeek 深度适配** | 思考模式 + 工具调用 + FIM + Anthropic 兼容 |
| **多源发现** | 自动扫描 Ollama、llama.cpp 端口、HuggingFace GGUF |
| **CLI + Web 双门** | CLI 脚本 + 浏览器仪表盘 + 对话页面 |
| **零框架依赖** | 只依赖 4 个 Python 包，不绑定任何 Agent 框架 |

### 1.4 核心命题

> 如何用最少的代码实现一个**真正可用**的模型管理中心？
> 1. pip install 后 3 步内看到仪表盘
> 2. 同时管 10 个模型不卡
> 3. GPU 监控零配置自动识别
> 4. 对话页面功能全（思考模式/流式/工具调用）
> 5. 新增模型不需要重启服务

## 二、做什么

### 2.1 产出物

1. **模型管理核心** — YAML 配置驱动的模型 CRUD，支持任意 OpenAI 兼容 API
2. **系统资源监控** — GPU (nvidia-smi) / CPU / 内存 / 磁盘 / Swap / 运行时间
3. **对话引擎** — 流式 SSE + 思考模式 + 工具调用 + FIM 补全
4. **多源发现** — Ollama / llama.cpp / HuggingFace 自动扫描
5. **Web 面板** — 仪表盘 + 模型库 + 对话页 + 模型管理 API
6. **CLI 工具** — 11 个子命令，覆盖全部管理操作
7. **DeepSeek 特化适配** — 思考模式参数、Anthropic 兼容层、错误重试、缓存统计

### 2.2 非目标（明确不做）

- ❌ **不是推理引擎** — 不运行模型，只管理模型
- ❌ **不是 Agent 框架** — 不提供记忆/工具系统/认知循环
- ❌ **不是模型市场** — 不提供模型托管/计费/分享
- ❌ **不是 Open WebUI 替代** — 定位是「模型管理中心」，不是「全功能 LLM 平台」

## 三、架构设计

```
用户
 ├─ CLI (arc) ────→ CLI 调度 (11子命令)
 └─ Web 浏览器 ──→ FastAPI (4 路由组)
                        │
                        ▼
               ┌────────────────────┐
               │  核心层 (kernel)    │
               │  ModelConfig / Config│
               │  YAML 读写          │
               └────────┬───────────┘
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
   ┌──────────┐  ┌──────────┐  ┌──────────┐
   │ 模型 CRUD │  │ 健康检查  │  │ 对话引擎  │
   │ /models  │  │ /health  │  │ /chat    │
   └──────────┘  └──────────┘  └──────────┘
          │             │             │
          ▼             ▼             ▼
   ┌──────────┐  ┌──────────┐  ┌──────────────┐
   │ 多源发现  │  │ 系统监控  │  │ DeepSeek适配 │

   │ llama.cpp│  │ RAM/Disk │  │ Anthropic   │
   │ HF       │  │ Services │  │ 重试/缓存   │
   └──────────┘  └──────────┘  └──────────────┘
```

### 3.2 模块分层

```
06-诺亚核心-模型管理与对话面板/
├── 源码/core/
│   ├── kernel.py         数据模型 + YAML 配置读写
│   ├── models.py         模型 CRUD

│   │   ├── chat_routes.py    对话 API
│   │   └── page_routes.py    页面路由
│   ├── deepseek/         DeepSeek 深度适配（7 文件）
│   │   ├── params.py         全量参数模型
│   │   ├── client.py         核心客户端
│   │   ├── parser.py         响应解析
│   │   ├── errors.py         错误分类+重试
│   │   ├── anthropic.py      Anthropic 兼容
│   │   ├── anthropic_router.py  Anthropic 路由
│   │   └── router.py         FastAPI 路由
│   └── static/templates/  Web 前端（6 文件）
└── 接入指南.md / 技术说明书.md / ...（6 文档）
```

### 3.3 核心设计决策

| 决策 | 方案 | 理由 |
|:----|:-----|:-----|
| 配置存储 | YAML (`~/.noah-core/config.yaml`) | 人类可读，CLI 友好，可git管理 |
| API 架构 | FastAPI + 零 ORM | 最小化依赖，4 个 pip 包搞定 |
| Web 前端 | 单页 HTML + 原生 JS + CSS | 零构建工具，零 Node.js |
| 对话协议 | OpenAI 兼容格式 | 最高兼容性，Ollama/llama.cpp/DeepSeek 统一接口 |
| DeepSeek 特化 | 深度适配（非妥协） | 思考模式/FIM/Anthropic 是真实需求，不做"也能用" |
| 多源发现 | 主动扫描 passive 端口 | 零配置发现本地模型 |
