## 二、模块拆解

### 2.1 kernel — 内核 / 数据模型 (105 行)

核心数据结构，所有模块的基石。

```
ModelConfig (数据类)
├── name: str            # 显示名称
├── provider: str        # openai / ollama / llamacpp
├── api_base: str        # API 地址
├── api_key_env: str?    # API Key 环境变量名
├── model_id: str        # 请求时用的模型 ID
├── real_name: str       # 真实模型名称
├── description: str     # 描述
├── notes: str           # 备注
├── type: str            # api / local
├── temperature: float   # 温度
├── max_tokens: int      # 最大 Token
└── api_key: str (属性)  # 从环境变量读取 Key

Config (数据类)
├── models: list[ModelConfig]
└── server: dict  →  {host, port, debug}
```

**设计决策**: 用 dataclass 而非 pydantic → 零额外依赖，100 行搞定。

### 2.2 models — 模型 CRUD (26 行)

三个函数覆盖全部模型操作——add / remove / get。直接操作 `kernel.py` 的配置，每次修改自动写回 YAML。

### 2.3 health — 健康检查 (79 行)

检查模型连通性的逻辑：

```
check_model_health(model)
│
├─ provider="ollama"    → GET /api/tags → 找匹配模型名
├─ provider="openai"    → GET /v1/models → 检查端点是否响应
└─ provider="llamacpp"  → GET /v1/models → 检查端点是否响应
    │
    └─ 返回 ModelStatus
         ├─ online: bool
         ├─ latency_ms: float
         ├─ error: str
         └─ status_emoji / status_text (属性)
```

### 2.4 chat — 对话引擎 (161 行)

兼容旧接口 + 提供新接口：

```
chat_completion(model, messages, extra_params, stream)
  → DeepSeek/OpenAI 兼容: 委托给 deepseek/ 模块
  → Ollama: 直接调用 /api/chat

deepseek_chat(api_key, api_base, messages, model, **kwargs)  [新接口]
  → 直接返回 DeepSeekChatResponse
  → 支持 thinking / reasoning / tools / FIM
```

### 2.6 discovery — 模型发现 (166 行)

三个发现源 + 两个下载器：

| 函数 | 功能 | 发现方式 |
|:-----|:-----|:---------|
| `discover_ollama_models()` | 发现 Ollama 本地模型 | 扫描 localhost:11434/api/tags |
| `discover_llamacpp_models()` | 发现 llama.cpp 服务 | 扫描 8080-11437 端口 |
| `search_hf_models(query)` | 搜索 HuggingFace GGUF | HuggingFace API → 过滤 GGUF |
| `pull_hf_model(repo_id)` | 下载 HF 模型 | huggingface-cli download |
| `pull_ollama_model(name)` | 下载 Ollama 模型 | ollama pull |

**设计决策**: 多源发现是核心差异化。Ollama 只管自己，我们管全部。

### 2.10 deepseek/ — DeepSeek 深度适配 (1,331 行)

这是诺亚核心最特化的模块。七个子文件覆盖 DeepSeek API 的方方面面。

#### params (231 行) — 全量参数模型

精确映射 DeepSeek 官方文档的所有参数：

```
DeepSeekChatParams
├── messages / model (必填)
├── thinking_type / reasoning_effort (思考模式)
├── temperature / top_p / max_tokens / stop (采样)
├── response_format (JSON 输出)
├── tools / tool_choice (工具调用)
├── stream / stream_options (流式)
├── logprobs / top_logprobs (对数概率)
└── user_id (用户隔离)

build_body() → dict  # 构建 API 请求体
build_fim_body() → dict  # 构建 FIM 请求体
```

**关键修正**: `thinking.type` 走 `extra_body`（非直接 body），`reasoning_content` 字段名（非 `thinking`）。

#### client (211 行) — 核心客户端

```
DeepSeekChatClient
├── chat(params) → DeepSeekChatResponse  # 非流式 + 重试
├── chat_stream(params) → Generator[StreamChunk]  # 流式
└── chat_fim(params) → DeepSeekChatResponse  # FIM 代码补全
```

**特性**:
- 自动去除 `/v1` 尾缀（兼容旧配置）
- 指数退避重试 + 抖动 jitter
- 错误分类（400/401/402/422/429/500/503）

#### parser (191 行) — 响应解析

非流式 + 流式（SSE）双模解析：

```
parse_chat_response(data) → DeepSeekChatResponse
parse_sse_chunk(raw_line) → StreamChunk | None
merge_stream_chunks(chunks) → DeepSeekChatResponse
```

**关键修正**: `delta.reasoning_content` 非 `delta.thinking`，`finish_reason: insufficient_system_resource` 处理。

#### errors (122 行) — 错误分类 + 重试

```
DeepSeekAPIError(code, message, detail)
  └─ retryable → 根据错误码判断

ErrorClassifier
  ├─ 400: 格式错误 / 401: 认证失败 / 402: 余额不足
  ├─ 422: 参数错误 / 429: 速率限制(可重试)
  └─ 500: 服务器故障(可重试) / 503: 服务器繁忙(可重试)

RetryHandler(max_retries=3, base_delay=1s)
  └─ 指数退避: 1s → 2s → 4s + 抖动(jitter)
```

#### anthropic (189 行) — Anthropic 兼容层

```
Claude Opus      → deepseek-v4-pro
Claude Haiku     → deepseek-v4-flash
Claude Sonnet    → deepseek-v4-flash

支持: text, thinking, tool_use, tool_result
不支持: image, document, redacted_thinking
```

#### router (286 行) / anthropic_router (101 行) — FastAPI 路由

```
POST /api/deepseek/chat/{name}             非流式
POST /api/deepseek/chat/stream/{name}      流式 SSE
POST /api/deepseek/fim/{name}              FIM 代码补全
GET  /api/deepseek/models                  模型列表
POST /api/deepseek/anthropic/messages      Anthropic 兼容
```

## 四、设计哲学

### 4.1 薄皮起步

> 单文件起步，功能到了自然拆。

诺亚核心最初所有代码在一个文件 `core/__init__.py` 里（~520 行）。直到架构稳定后才拆分为 15 个模块。这种 "Thin Crust" 策略的好处：
- 零抽象负债 —— 不需要提前设计接口
- 重构成本低 —— 整个核心在一个文件里，改什么一翻就到
- 迭代快 —— 不需要跨文件跳转

### 4.2 特化而非通用

> 功能要做到「专业版」而不是「也能用版」。

DeepSeek 适配是典型案例：
- 思考模式（thinking type/reasoning_effort）不是「反正能调 API」，而是精确处理 `extra_body` 路径、字段名映射、禁用冲突
- 错误重试不是简单 `try/except`，而是根据错误码智能区分可重试/不可重试

用户确认：「特色不是兼容而是特化」。

### 4.3 零框架依赖

> 不依赖任何 Agent 框架，pip install 就可用。

四个依赖都是标准 Python Web 库：
- `pyyaml` — YAML 读写
- `fastapi` + `uvicorn` — Web 服务
- `jinja2` — 模板（仅用于未来扩展，当前页面是原生 HTML）

无 LangChain、无 Hermes、无任何 Agent SDK。

### 4.4 CLI + Web 双门

所有功能都有 CLI 命令和 Web UI 两种打开方式：
- CLI 用于自动化/批量/调试
- Web UI 用于日常管理/监控/对话

但用户的日常交互以 Web UI 为主。「一张 Web 表单的可见度远超十个 CLI 演示」。
